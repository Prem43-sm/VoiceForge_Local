CODEx MASTER PROMPT — FREE LOCAL VOICE PACK BUILDER

PROJECT NAME

VoiceForge Local — Offline Voice Clone & Reusable Voice Pack Studio

OBJECTIVE

Build a complete, production-minded, FREE, LOCAL Windows PC application
that lets a user provide one or more authorized voice recordings
(MP3/WAV/M4A/FLAC where supported), process them, create a reusable
voice profile/voice pack, and then use that voice pack from other AI
projects to synthesize speech locally.

The core idea is:

    INPUT AUDIO
        ↓
    AUDIO VALIDATION
        ↓
    PREPROCESSING / CLEANING
        ↓
    VOICE MODEL / SPEAKER EMBEDDING
        ↓
    VOICE PACK CREATION
        ↓
    SAVE VOICE PACK
        ↓
    FUTURE PROJECT
        ↓
    TEXT → VOICE PACK → WAV/MP3

The application must NOT depend on paid cloud APIs for its core
functionality. It must work locally after models/dependencies have been
downloaded.

IMPORTANT LEGAL / SAFETY REQUIREMENT

The application must only be used to clone or reproduce voices that the
user has permission/authorization to use. The UI must clearly state this
requirement.

Do NOT design the application around impersonating a real person without
permission, bypassing platform safeguards, fraud, deception, identity
theft, or evading voice-authentication systems.

Do not market or label the feature as an “exact celebrity voice copier.”
Instead, call it a voice-cloning / voice-reproduction system and clearly
distinguish authorized voice cloning from fictional voice design.

The application may support arbitrary user-provided voices technically,
but it must include an authorization confirmation before creating a
voice pack:

“I confirm that I own this voice recording or have permission to
reproduce this speaker’s voice.”

Store this acknowledgement in the voice-pack metadata.

Primary OS: - Windows 10/11 64-bit

Primary hardware: - NVIDIA GPU preferred - CUDA-capable GPU preferred -

MODEL STRATEGY

The application must distinguish between two fundamentally different
approaches:

A. ZERO-SHOT / FEW-SHOT VOICE CLONING

The model uses a short reference recording to reproduce the speaker
characteristics without training a new neural network from scratch.

This should be the default MVP approach because it is much faster and
more practical for a local desktop application.

The Codex implementation should investigate and integrate a suitable
free/open-source local model such as: - XTTS-v2 or another compatible
Coqui-family implementation if licensing/runtime compatibility permits -
F5-TTS or another compatible open-source voice cloning model -
Chatterbox or another compatible open-source local TTS model - OpenVoice
or another compatible voice-conversion/TTS model

Do NOT blindly install every model.

Pick ONE primary model that: - supports local inference - supports
reference-speaker cloning - works on Windows - has a clear open-source
license - has manageable VRAM requirements - supports the desired
language(s), especially Hindi/English where possible

Add other engines only through the plugin interface.

The Codex agent must verify model license, supported languages, Windows
compatibility, Python/PyTorch compatibility, and GPU requirements before
selecting the default engine.

B. FULL MODEL TRAINING / FINE-TUNING

This is optional and should NOT be required for the MVP.

The UI may later support training/fine-tuning a dedicated speaker model
using a larger authorized dataset.

Do not pretend that a 5-second MP3 can train a high-quality neural TTS
model from scratch.

Explain in the UI:

-   Short reference audio → speaker-conditioned / zero-shot cloning
-   Larger clean dataset → optional fine-tuning
-   More clean and diverse speech → generally better speaker consistency

VOICE PACK CONCEPT

The most important feature is the reusable VOICE PACK.

A voice pack is NOT simply one WAV file.

It should be a directory containing everything needed to identify and
reuse the voice.

Example:

voice_packs/ └── jarvis_style_demo/ ├── voicepack.json ├──
speaker_embedding.bin ├── reference_audio/ │ ├── reference_01.wav │ └──
reference_02.wav ├── preview/ │ └── preview.wav ├── metadata/ │ ├──
source_info.json │ └── preprocessing.json ├── engine/ │ └──
engine_config.json └── README.txt

If the selected engine needs additional model-specific assets, store
them under:

    engine_assets/

Do not duplicate huge base model files into every voice pack unless
absolutely necessary.

The voice pack should reference a locally installed base model by
ID/version.

AUDIO QUALITY ANALYSIS

Before creating a voice pack, analyze:

1.  Duration
2.  Sample rate
3.  Channel count
4.  RMS loudness
5.  Peak level
6.  Clipping
7.  Silence ratio
8.  Noise estimate
9.  Speech ratio
10. SNR estimate where practical
11. DC offset
12. extremely low/high volume
13. duplicate/near-duplicate recordings

Give a quality score:

    0–39  Poor
    40–59 Fair
    60–74 Good
    75–89 Very Good
    90–100 Excellent

Do not claim the score is scientifically definitive. It is an
engineering heuristic.

PREPROCESSING PIPELINE

Create a non-destructive preprocessing pipeline.

Typical stages:

1.  Decode using FFmpeg
2.  Convert to mono
3.  Resample to model-required sample rate
4.  Remove leading/trailing silence
5.  Detect long internal silences
6.  Normalize loudness
7.  Optional gentle denoising
8.  Optional dereverberation
9.  Detect clipping
10. Segment speech
11. Remove unusable segments
12. Generate clean reference clips

Do NOT aggressively process audio.

Over-processing can damage speaker identity.

Keep: - original input - processed audio - generated reference

separate.

REFERENCE AUDIO SELECTION

If multiple files are provided, rank them.

Prefer: - clean speech - minimal background noise - little reverb -
natural speaking - varied phonemes - stable microphone characteristics -
no music - no overlapping speakers

Reject or warn on: - music - movie dialogue with effects - heavy
background noise - multiple people speaking - extreme compression -
distorted audio - very short non-speech audio

Do not automatically include every uploaded file in the final speaker
reference.

Let the user manually select references.

IMPORTANT LIMITATIONS

Clearly explain:

-   Voice cloning quality depends on reference audio and model.
-   Very short audio may produce unstable results.
-   Background noise can affect cloning.
-   Some languages may not be supported by every engine.
-   A voice pack is not necessarily a full neural model.
-   Base models remain separate from voice profiles.
-   CPU inference can be slow.
-   Different engines produce different voice characteristics.

DO NOT CLAIM: “Any 3-second MP3 gives perfect cloning.”

Instead say:

“Short references may work with compatible zero-shot models, but longer
clean speech generally provides better and more stable speaker
representation.”

PRONUNCIATION DICTIONARY

Allow user-defined replacements.

Example:

{ “JARVIS”: “JAR-vis”, “GPU”: “G P U” }

Do not alter source text permanently.

Use a preprocessing layer:

original text ↓ pronunciation normalization ↓ TTS

Keep original text in job metadata only if the user enables it.

PAUSE / PERFORMANCE MARKUP

If supported by the selected engine, optionally support:

[PAUSE 500ms]

[EMPHASIS]

[SLOW]

But do not invent unsupported SSML.

Translate these controls into engine-specific parameters.

If unsupported, disable them.

NO HIDDEN NETWORK

The application must not silently upload: - reference audio - generated
audio - user text - voice embeddings

to third-party services.

Any network request must be explicit and documented.

DEFAULT NETWORK POLICY: - localhost allowed - model downloads only when
user initiates - no telemetry

SOURCE CODE QUALITY

models where appropriate - structured logging - docstrings - clear
naming - modular classes - dependency injection where useful - unit
tests

Avoid: - giant functions - global mutable state - hard-coded paths -
hard-coded model IDs throughout the code - duplicated preprocessing
logic - UI directly calling model internals

UI must communicate with services.
